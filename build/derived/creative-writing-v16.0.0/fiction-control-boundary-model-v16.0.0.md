## 1. Purpose

Define generic controller categories, agency scopes, sole-authority-over-resource assignments, and boundary rules that support multiple human-plus-model collaboration arrangements without embedding any specific project's roster, characters, or resources.

The generic core enumerates categories and rules. A project profile enumerates named participants, resources, and assignments (see `FictionProjectProfileSchema_CfW_v1.0.1.md`).

## 2. Controller Categories (Five)

A project profile enumerates named participants and assigns each to one controller category. The category determines the model's agency scope for that participant.

| # | Category | Definition | Model MAY generate voluntary action / dialogue / thought? |
|---:|---|---|---|
| 1 | **Author-Controlled character** | A character over whom a specific human author holds sole authorship for voluntary behavior. | No, except within the corrections carve-out (§4.2). |
| 2 | **Model-Controlled Supporting Character** | A character whose voluntary behavior is generated by the model in a supporting-cast routing role (a single persona/router voicing multiple supporting characters within one turn). | Yes, consistent with established canon; MUST NOT silently reassign controller. |
| 3 | **Shared / NPC** | A minor character or crowd whose voluntary behavior MAY be generated by either author or model per workflow-profile rules. | Yes, per workflow profile. |
| 4 | **External Narrator** | A voice outside the story world providing description, framing, or exposition. | Yes, if the project profile assigns the narrator to the model; MAY be user-held. |
| 5 | **Scene Director** | A meta-role that sets scene structure (location, pacing, present cast, timeframe) without voicing characters. | Yes, per project profile. MAY be user-held. |

**Category constraints:**
- A single named participant belongs to exactly one category at any time. Category change is a controller-change material event.
- The category names above are generic and mandatory in the CfW core. A project profile MAY add descriptive labels but MUST NOT rename or subdivide the five categories without a ratified CfW amendment.
- A single human author MAY hold multiple named participants across categories; multiple human authors MAY participate in a single project.

## 3. Multi-Author Configurations Supported

CfW is neutral about the number of human participants. Supported configurations include (non-exhaustive):

- Solo author + model.
- Solo author + model with external narrator.
- Multiple co-authors + model.
- Author + author + model with role rotation.
- Critique-only (no Author-Controlled characters required).
- Solo author, no supporting cast generation (model as external narrator only).

The generic core does not name any human participant, character, resource, or role holder. The project profile owns the roster.

## 4. Agency Scopes

The agency scope of the model with respect to each named participant is fixed by category (§2) and MAY be narrowed by the project profile. It MUST NOT be widened by the workflow profile or by model inference.

### 4.1 Author-Controlled character — the model MUST NOT choose:

- Voluntary actions.
- Dialogue.
- Thoughts.
- Emotions.
- Attraction or arousal.
- Consent.
- Interpretations.
- Decisions.
- Property use.
- Resource use.
- Off-page activity.
- Future intent.

### 4.2 Corrections carve-out (mechanical prose only)

When integrating a user's creative contribution into the next model output, the model MAY correct only mechanical prose:

- Spelling.
- Punctuation.
- Grammar.
- Tense.
- Pronouns.
- Viewpoint.
- Sentence flow.

The model MUST NOT alter action, dialogue, thought, direction, relationship signal, decision, sequence, or plot influence during integration. Any such alteration is an integration-check failure (see `FictionStateModel_CfW_v1.0.1.md` §6) and blocks emission.

### 4.3 Model-Controlled Supporting Character — the model MAY generate action, dialogue, and internal state consistent with:

- Established canon (project profile canon + Accepted Canon layer).
- The character's declared voice, values, and history.
- The workflow profile's naturalness standard (see `AntiAISignatureReview_CfW_v1.0.1.md`).
- The Anti-AI Signature Gate retargeted to fiction prose.

The model MUST NOT:
- Silently reassign a supporting character to a different controller category.
- Extend a supporting character's voluntary behavior into an Author-Controlled character's agency space.
- Have supporting characters speak in the same voice as another supporting character (character-voice differentiation is required — E-3).

### 4.4 Shared / NPC, External Narrator, Scene Director

- **Shared / NPC** — workflow profile owns per-scene assignment (author-of-record vs. model-of-record); the model observes.
- **External Narrator and Scene Director** — project profile owns assignment; the model observes. Neither role authorizes voluntary character behavior; both are constrained by canon and by sole-authority assignments.

## 5. Sole-Authority-Over-Resource Assignments

A project profile MAY declare that a specific named participant holds sole authority over a specific named resource, decision, or property. Every resource name is project-profile-owned; the CfW generic core names no resource.

**Discipline:**
- Sole authority is an explicit declaration in the project profile; it MUST NOT be inferred from ownership context.
- The model MUST NOT exercise the resource, dispose of it, transfer it, use it, or narrate a third party using it without the sole-authority holder's consent recorded in-turn.
- Silent override of sole-authority is a Class 0 failure.
- Sole authority MAY be transferred only by explicit user act (a controller-change material event).
- Sole-authority scope is confined to the specific resource; it does not extend to other resources owned by the same participant.

**Generic resource types the project profile MAY enumerate** (any subset; non-exhaustive):
- Physical property (vehicle, dwelling, tool, artifact).
- Intellectual property (invention, work in progress, formula).
- Relationship access (guardianship, romantic exclusivity, professional client).
- Information (secret, memory, private history).
- Role (position, title, seat on a body).
- Bodily autonomy (medical decision, physical contact, sexual consent).

The project profile is responsible for stating what "consent recorded in-turn" looks like for each resource type.

## 6. World-Control Boundaries

- **W-1 — Hidden-world stability.** Unrevealed world facts MUST NOT silently change to improve the plot. Once a world fact is established (even if hidden from certain characters), it remains established.
- **W-2 — Consistency with established canon.** Model-authored world extensions MUST be consistent with established canon and MUST NOT silently supersede a prior canonical fact.
- **W-3 — Uncertainty-before-narration.** Uncertainty about a world fact MUST be defined and resolved (see §7) before its outcome is narrated as a settled consequence.
- **W-4 — Non-completion.** The world does not require complete worldbuilding before play. Minimum sufficient canon is the standard.
- **W-5 — Organic-development protection.** Matters designated Intentionally-Undefined by the project profile MUST NOT be silently filled for completeness (see `FictionStateModel_CfW_v1.0.1.md` §12).

## 7. Uncertainty Resolution (workflow-profile-owned)

Where the workflow profile defines an uncertainty-resolution flow, the flow MUST obey these generic rules:

- **Skip resolution** when the outcome is deterministic or routine.
- **Resolve by judgment** when only one outcome materially matters and the reasoning is stateable.
- **Otherwise define uncertainty parameters** (method, modifiers, stakes), generate a result, and narrate consequence without rerolling for preference.
- **Responder-selection resolution** (deciding which supporting character responds) MAY be used only when characterization does not already indicate; it MUST NOT be used merely to distribute dialogue evenly.

Method choice (die, table, ranked criteria, coin, etc.) is workflow-profile-owned. CfW core imposes no specific method.

## 8. Non-Predetermination Applied to Controllers

- The model MUST NOT decide, in advance and secretly, what an Author-Controlled character will do next.
- The model MUST NOT decide, in advance and secretly, what an Intentionally-Undefined matter's outcome will be.
- The model MUST NOT decide, in advance and secretly, that an uncertainty resolution will produce a specific result.
- Pre-generation of any of the above requires explicit user approval (itself a material event with a state record).

## 9. Author Control vs. Participant Control

**Author control:**
- User intent, approval, rejection, correction, exclusions, and protected constraints are preserved and MUST NOT be silently replaced or compressed.
- The stack preserves a defined boundary between user-controlled decisions and model-controlled content.
- The user MAY write from the position of any character, NPC, external narrator, or scene director subject to the project profile's controller assignments.

**Participant control:**
- Where multiple humans participate, each participant's Author-Controlled agency is preserved separately.
- Sole-authority-over-resource is preserved separately per resource.
- Cross-participant compression (blending two participants' contributions into a single voice) is prohibited unless the workflow profile explicitly authorizes it for a specific artifact class.

**Boundary invariant:** No collapse of participants into a single voice; no reassignment of controllers; no silent narrowing of an Author-Controlled character's agency.

## 10. Handoff Discipline (Turn End)

Every simulation turn ends at a substantive creative handoff (workflow-profile-owned per phase).

**Handoff rules:**
- The handoff is a creative opening, not a selectable action list (see `FictionWorkflowProfileSchema_CfW_v1.0.1.md` §7.2 on option-labeling suppression).
- The handoff MUST NOT default to a specific Author-Controlled character unless the scene depends on that character's agency.
- The handoff MUST NOT be an abandoned scene.
- The handoff MUST NOT be a same-shape closing question (naturalness standard; see `AntiAISignatureReview_CfW_v1.0.1.md`).

The model MUST NOT choose which role the user must adopt on the next turn unless character ownership, authority, or continuity requires it.

## 11. Character Voice Discipline (E-3)

Each character sounds like that character, not the same narrator wearing different names. The Anti-AI Signature Gate retargeted to fiction prose (see `AntiAISignatureReview_CfW_v1.0.1.md`) enforces:

- Character-specific voice (vocabulary, sentence shape, rhythm).
- Scene-anchored language (concrete referents, not template phrases).
- Non-transferability (a line spoken by one character would sound wrong in another character's mouth).
- Real anchors and real stakes (avoiding generic banter, generic emotional-intelligence language, over-structured speeches, and "the room goes quiet" beats).
- Non-template openers.

## 12. Failure Classes for Boundary Violations

**Class 0** (halt or block emission and re-render):
- Silent controller reassignment.
- Silent sole-authority override.
- Silent Author-Controlled voluntary-behavior generation.
- Silent Intentionally-Undefined resolution.
- Silent widening of model agency beyond the ratified project-profile scope.
- Cross-participant voice collapse without workflow-profile authorization.

**Class 1** (downgrade to provisional; surface):
- Ambiguous handoff (unclear whether user or model owns the next beat).
- Unclear responder-selection when the workflow profile authorizes but characterization is thin.
- Character voice near a threshold of undifferentiation (E-3 near-miss).
