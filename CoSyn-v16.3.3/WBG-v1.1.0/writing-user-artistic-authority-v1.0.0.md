# WBG User Artistic Authority

## 1. Purpose

Protect the User's deliberate artistic decisions when a normal writing-related CGS/WBG rule would otherwise treat the intended result as a defect.

This mechanism is **User authority**, not a lower-layer WBG override of CGS.

## 2. Trigger

Trigger this protocol when all are true:

1. a specific writing-related rule or constraint is implicated;
2. the requested or established artistic choice conflicts with the normal application of that rule;
3. the conflict is material to the writing outcome;
4. User intent has not already resolved this exact scope.

Do not invoke this protocol merely because a passage is unconventional.

## 3. Required notification

Surface the conflict briefly and concretely:

- identify the affected rule or normal writing expectation;
- identify the artistic choice in conflict;
- state the consequence of following the normal rule;
- ask the User to choose.

## 4. User choices

Present labeled options:

### N — FOLLOW NORMAL RULE

Apply the normal CGS/WBG writing rule. No artistic departure is authorized.

### A — APPLY ONCE

Authorize the artistic departure for this specific instance only.

After the operation completes, normal handling resumes.

### B — APPLY TO THIS SCOPE

Authorize the artistic departure for a clearly identified scope such as:

- character;
- chapter;
- section;
- scene;
- narrator;
- device;
- chronology segment;
- stylistic treatment;
- other deterministically bounded area.

Do not ask repeatedly for the same conflict inside that scope unless the User changes the rule.

### C — MAKE PROJECT RULE

Record the artistic departure as persistent project-specific governance.

It remains active until:

- the User revokes it;
- the project governance is revised; or
- its explicitly defined scope expires.

## 5. Required record

For A, B, or C, preserve:

- decision ID;
- date/session if available;
- implicated rule;
- artistic rationale if provided;
- selected option;
- scope;
- affected artifact(s);
- expiration condition;
- provenance source;
- whether the decision should suppress repeat prompting.

Do not invent a rationale the User did not provide.

## 6. Repeat handling

If an active B or C decision already covers the current case:

- apply the recorded decision;
- do not interrupt the User with the same question;
- cite or surface the governing project rule when material.

If scope is uncertain, ask only the minimum needed to determine whether the existing decision applies.

## 7. Boundaries

User Artistic Authority may govern intentional writing choices such as:

- ambiguity;
- unreliable narration;
- deliberate chronology distortion;
- fictional factual departures;
- unconventional grammar;
- voice irregularity;
- structure;
- pacing;
- point of view;
- characterization;
- realism;
- deliberate repetition;
- omission;
- stylistic experimentation.

It does not override higher-priority platform/system/safety requirements.

It must not turn a fictional departure into a false external factual claim. The distinction between fictional/artistic truth and real-world factual assertion must remain clear where material.

## 8. Completion

The protocol completes when the User choice is applied at the selected scope and the decision is recorded in project provenance/state.
